vault-watch-agent: how the code fits together

A reading guide for developers: modules, the graph state, where the model is called, and how a paused run survives.

English · Français · Overview · README

About 3,000 lines of Python in src/vault_watch_agent/, a static page without build step, and tests that run the whole graph against a fake model and a throwaway git repository. Start with graph.py: everything else either feeds it or drives it.

Modules and their dependencies

Two rules shape this graph:

  • One door to the model. Only llm.py imports anthropic. Every other module receives an object with a parse(system, prompt, schema, effort, node, context, web) method (the LLM protocol), so the tests swap it for a fake.
  • One door to the guide. Reading, searching and editing pages go through vault.py; calls to git, gh and the guide's own scripts go through inputs.py. The model never touches a file.

The graph, node by node

build(deps, checkpointer) receives a Deps dataclass: the guide path, the model for the reasoning steps (llm), the model for the English mirror (translator), whether to run the cross-check, the GitHub repository and base branch, today's date. Nodes are closures over deps, so a test builds the same graph with fakes.

The state that flows through it

WatchState (state.py) is a TypedDict of plain JSON values: a paused run is serialised by the checkpointer as is. Each node returns only the keys it changes.

⊕ marks the two keys with a reducer (Annotated[list, operator.add]): the parallel propose branches append their proposals and their token usage instead of overwriting each other. The Pydantic classes are the output_format of the model calls: an answer that does not validate is an error, not a guess.

How a run pauses and resumes

The CLI and the web page share the same SQLite file and the same thread ids, so a run started from one can be finished from the other. The web server runs the graph in a background thread and streams graph.stream(stream_mode="updates") to the page as server-sent events.

Fix runs enter the graph in the middle

A fix run makes its own proposals, then tells LangGraph they came out of propose: from number on, it is the same graph, the same report, the same review and the same pull request as a watch. A translation fix sets mode = "translation" and skips the French cross-check.

No test calls the real API. vault-watch eval is the measure against real watches (results in metrics/eval/).

Where to look first

  1. state.py: what a run knows at each step.
  2. graph.py, build(): the nodes and the edges, then the node you care about.
  3. llm.py: caching, web tools, cost journal, in about 120 lines.
  4. vault.py, check() and apply(): why the model cannot damage a page.
  5. web.py or cli.py: how runs are started, paused and resumed.
